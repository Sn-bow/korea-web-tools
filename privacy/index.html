Privacy

Your recipe is calculated
inside this browser.

This release has no accounts, ads, external analytics services or tracking scripts, external fonts, external APIs, or code that sends ingredients to a server. Limited server-side page request counts and separate error logs are described below.

What is stored?

When you only calculate
Inputs and results stay in the current page's memory. They are not automatically saved to a server or browser storage.
When you choose “Save in this browser”
One checklist is stored under hanteuldeoh.prep.v1 in localStorage: its name, original and edited ingredient inputs, pan inputs and checked items. The next save overwrites it. Save again to keep later edits or checkbox changes.
Deletion and reset
Confirming “Delete saved copy” removes the saved checklist. “Start over” clears the current screen but keeps the separately saved checklist. Clearing site data in your browser can also remove the saved copy.
Language preference
Choosing a language stores only your English or Korean preference under recipepilot.language.v1. This is separate from recipe saving. Clearing site data removes the preference too. You can still switch languages on the current page if storage is blocked.

The saved copy is available on the same device, browser and site address. It does not sync to other devices. Avoid saving on shared devices, or delete the saved copy afterward. Browser settings and file URLs may block storage.

Partner Rotation: names, history and optional storage

Partner Rotation processes names or nicknames, attendance, and completed pair/rest history in the current page. Participant data is not sent to the server. Internal participant IDs link history when names change; they are used only within group data and are not visitor-tracking IDs.

Choosing “Save on this device” stores one group’s roster, attendance and completed history under partner-rotation:session:v1 in localStorage. Previews are excluded and changes are not saved automatically. After reloading, choose “Restore saved group” explicitly. This item is separate from the recipe checklist.

Confirming “Reset everything” removes the current group and this tool’s saved browser copy. Downloaded backups remain. The saved copy is tied to the same browser, device and site origin, without automatic sync. Clearing site data can remove it.

If you choose copying, printing or backup, participant names and history are included in the clipboard, selected output destination or unencrypted JSON file. Restoring a backup replaces the current group but does not automatically overwrite browser storage. Press Save to keep it. You manage the destination and retention of those copies.

The new partner-rotation route has not been added to the current fixed page request-count set. The count scope and separate error-log notice below remain unchanged.

Page request counts

To check whether the site is being used, we count completed HTTPS GET requests for a fixed set of pages that return successful HTML responses (status 200). HTTP redirects, static images, styles and scripts, status checks, and paths outside the fixed set are excluded.

Count records contain only a UTC hour or date, a predefined page name and category (qa, known_crawler, other), status 200, and a request count. They do not store original IP addresses, cookies, recipe inputs or calculation results, URL queries or search terms, full URLs, referrers, original User-Agent or header values, or device, session or request identifiers. No raw request files are created for these counts.

Our own checks use one fixed public header value and are labeled qa; the value is not a user, device or test-run identifier. A small list of known crawler names in the User-Agent produces known_crawler; remaining requests are other. QA takes precedence. These labels are spoofable and may miss bots. Other does not mean verified human traffic. Repeated requests and bots may be included, so counts are not unique visitors or numbers of people. Delivery failures or downtime can cause missed requests.

This counting adds no external analytics service, tracking script or cookie, or browser identifier. Checklists and language preferences you choose to save in the browser are separate.

Hourly totals are kept only in memory for up to 23 UTC hour buckets and disappear when the counter restarts. Daily totals for each page and category are stored in one access-restricted file capped at 64KiB; the old and temporary files together are capped at 128KiB during replacement. During normal operation, the current UTC date and previous 28 dates are retained, with hourly cleanup intended to keep retention shorter than 30 days. No raw request files or rotated archives are created. Physical deletion can be delayed while the server is off or cleanup or disk operations fail. Expired totals are excluded from queries and deleted on the next startup or successful cleanup. Totals not yet saved before an interruption may be lost.

Counting starts after this notice is published. Visit data from the earlier period when ordinary access logging was disabled cannot be recovered.

This description applies only to the count records. Separate error logs may contain request information such as IP addresses and request paths or queries, with a different retention policy. All warning-level diagnostics in the general HTTPS page-serving location are suppressed to prevent count-transport failures from adding request information to WARN logs. Error-level and more severe diagnostics there, and records in other locations, remain. Read the separate error-log notice below. This does not mean the server as a whole never processes or records information such as IP addresses.

Server requests and error logs

The web server handles requests for pages and static files. Requests for a fixed set of pages are counted using the limited aggregate process described in this notice. There is no feature that sends recipe inputs or calculation results to the server.

Error logs are enabled for troubleshooting. They may include the IP address, request path and time of a request that caused an error. Server logs are not public; access is restricted through server file permissions.

An error-log rotation rule file exists, but the tool and schedule needed for automatic rotation and deletion were not active when checked. No retention period or deletion date is guaranteed, including deletion after 14 days. This does not mean the server processes or records no information.

Printed files and device security

Printed checklists or PDFs saved through your browser may remain on your selected device or printer. This tool cannot delete those copies or control access to them.

Avoid putting personal or sensitive information in ingredient or checklist names. This notice describes the current code and verified server configuration; it is not a legal review or compliance certification.
